# Next-wave local editing workflows

This change extends the published 0.2 implementation with four specific workflows. It does not establish complete Canva parity. The [all-tier comparison](feature-comparison.md) records the broader catalogue; the delta below records these four source workflows and their remaining limits. The published 0.2 baseline and its receipts remain separate from this extension. Official pages were checked on 10 October 2026. Plan entitlements and authenticated implementation details can change.

| Workflow | Official observable behaviour | Stencil implementation | Remaining scope |
| --- | --- | --- | --- |
| Page order | Pages can move using arrows or thumbnail/grid dragging. [Manage pages](https://www.canva.com/help/manage-pages/) | Move earlier, later or to a numbered position; durable page IDs, elements and active selection stay together. JSON, library, PDF, presentation and video use the new order. | No draggable page grid, multiple-page selection or Canva's larger page limit. |
| Guides and rulers | Adjustable guides and rulers support precise alignment; guide presets and locking are documented. [Page settings](https://www.canva.com/help/page-view-settings/), [guides](https://www.canva.com/help/adding-and-removing-guides/) | Per-page fractional pixel guides, ruler click-to-add, line dragging and exact field edits; visible/ruler switches; independent guide/layer/page snapping sources with 1–30 screen-pixel distance. | No guide locking, grid presets, physical-unit rulers, margins, bleed or print safe zones. Exact reference snap behaviour is unknown. |

Page order and transparent page image/SVG exports have local implementations of the selected behaviour. Guides and the broad tables/charts category remain partial. This document separates source implementation from native-browser qualification; the [verification receipt](../verification.md) records the checked release and platform rather than promising a new run prematurely.

## Data and editing rules

Tables keep `data.columns` (1–8 non-empty headings) and `data.rows` (0–50 rows with the same number of string cells). Headings are at most 100 characters and cells 1,000 characters. Duplicate headings are allowed because cells are retained as an ordered matrix. New tables are single editable layers; older primitive groups are preserved as they were, with no inferred conversion.

Charts keep `data.kind` (`bar`, `line` or `pie`), ordered `labels` and corresponding finite `values` (0–1,000,000,000). There are 1–30 points. Bar/line charts accept all-zero data; pies require a positive total, and a single positive slice renders a full circle. A retained palette controls pie colours. Font size, text colour, visibility flags and table border/header styles remain editable. Common position, size, rotation, opacity, grouping, lock, hide and flip fields apply to these elements. Undo, copy/paste, page duplication, local library and shared revision storage carry independent copies of the source data.

CSV is plain local text. Quotes, embedded newlines, commas and Unicode survive round trips. It never evaluates a formula, opens a URL or fetches a connected sheet. Invalid or over-limit data leaves the current document intact. A failed browser storage write keeps the new design in memory and preserves the unsaved/error status instead of announcing a successful saved creation.

Guides have stable IDs and an `x` or `y` coordinate within their page bounds. Page duplication and bulk creation generate new guide IDs. Resizing scales their coordinates with the layout, or clamps them if layout scaling is disabled. Guide visibility controls display; snapping has its own separate switch. The drag toolbar can bypass all snapping, and Alt bypasses it for an individual gesture. Rulers and guides are editor UI and never enter page artwork.

## Strict migration and rollback data

New documents use schema version 3. Imports validate v1/v2 against their original field allowlists before adding defaults. Existing old fields, IDs, page order, crop/filter settings and primitive chart/table groups are preserved. Migration adds only per-page `transparentBackground: false`, an empty guide list and independent default guide settings. The unchanged default artwork exports exactly as before.

Before an automatic save replaces a stored v1/v2 active document, the exact original JSON string is copied to a distinct local key beginning `stencil-studio.document.v1.migration.v3.` and read back for verification. Library writes similarly retain the whole exact original library under `stencil-studio.library.v1.migration.v3.`. A backup collision cannot overwrite another original. A failed or silently discarded backup blocks replacement, including an otherwise writable active key. Current migrated content remains available in memory and JSON export. The File menu offers the original active-document bytes for download when available.

Browser storage can still fill, and clearing browser data removes its backups. Export files before clearing data or changing browsers. The older v2 application cannot consume newly added v3 fields; keep the preserved original for rollback. Configured shared workspaces validate and retain v3 documents through the same model validator; they require the matching server/app version. No service protocol, credentials, provider, audio/video engine or public 0.2 branch is changed by this document model extension.
