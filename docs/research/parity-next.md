# Editing features added in 0.3

This page records four editing features from the 0.3 release. For the current tools and saving format, see the [design guide](../consumer-design.md). The [all-tier comparison](feature-comparison.md) covers the broader catalogue; the table below covers these four changes and their limits. The 0.2 source and results remain separate. Official pages were checked on 10 October 2026; plan access and signed-in behaviour can change.

| Workflow | Official observable behaviour | Stencil implementation | Remaining scope |
| --- | --- | --- | --- |
| Page order | Pages can move using arrows or thumbnail/grid dragging. [Manage pages](https://www.canva.com/help/manage-pages/) | Move earlier, later or to a numbered position; durable page IDs, elements and active selection stay together. JSON, library, PDF, presentation and video use the new order. | No draggable page grid, multiple-page selection or Canva's larger page limit. |
| Guides and rulers | Adjustable guides and rulers support precise alignment; guide presets and locking are documented. [Page settings](https://www.canva.com/help/page-view-settings/), [guides](https://www.canva.com/help/adding-and-removing-guides/) | Per-page fractional pixel guides, ruler click-to-add, line dragging and exact field edits; visible/ruler switches; independent guide/layer/page snapping sources with 1–30 screen-pixel distance. | No guide locking, grid presets, physical-unit rulers, margins, bleed or print safe zones. Exact reference snap behaviour is unknown. |
| Transparent designs | PNG and SVG export support transparent backgrounds for eligible plans. [Download types](https://www.canva.com/help/download-file-types/) | Persistent Artboard transparency switch removes the page background from SVG and PNG. Original Background colour remains available for flattening JPEG/raster PDF. Checkerboard and editor guides are omitted from exports. | No CMYK, bleed/crop marks, selected-page export sets or transparent video codec claim. |
| Retained tables/charts | Tables expose cell/row/column editing; charts retain editable data and allow chart-type changes. [Tables](https://www.canva.com/help/adding-and-deleting-tables/), [charts](https://www.canva.com/help/charts/), [chart types](https://www.canva.com/en_in/help/interactive-charts/) | Native table/chart elements retain validated data and style fields. A real grid reopens the source; CSV import/copy supports quoted text. Tables have editable columns/cells, row addition/deletion and last-column removal; bar/line/pie charts regenerate from one dataset. | No arbitrary row/column reordering, merged cells, cell-specific styles, formulas, multiple datasets, external connectors, 30+ chart catalogue or AI chart generation. |

Stencil provides local page ordering and transparent image/SVG downloads. Guides and the wider tables/charts category remain partial. This document describes the source; [release checks](../verification.md) record which release and platform were tested.

## Data and editing rules

Tables keep `data.columns` (1–8 non-empty headings) and `data.rows` (0–50 rows with the same number of string cells). Headings are at most 100 characters and cells 1,000 characters. Duplicate headings are allowed because cells are retained as an ordered matrix. New tables are single editable layers; older primitive groups are preserved as they were, with no inferred conversion.

Charts keep `data.kind` (`bar`, `line` or `pie`), ordered `labels` and corresponding finite `values` (0–1,000,000,000). There are 1–30 points. Bar/line charts accept all-zero data; pies require a positive total, and a single positive slice renders a full circle. A retained palette controls pie colours. Font size, text colour, visibility flags and table border/header styles remain editable. Common position, size, rotation, opacity, grouping, lock, hide and flip fields apply to these elements. Undo, copy/paste, page duplication, local library and shared revision storage carry independent copies of the source data.

CSV is plain local text. Quotes, embedded newlines, commas and Unicode survive round trips. It never evaluates a formula, opens a URL or fetches a connected sheet. Invalid or oversized data leaves the current design unchanged. If browser saving fails, the new design stays open with an unsaved warning so it can be exported.

Guides have stable IDs and an `x` or `y` coordinate within their page bounds. Page duplication and bulk creation generate new guide IDs. Resizing scales their coordinates with the layout, or clamps them if layout scaling is disabled. Guide visibility controls display; snapping has its own separate switch. The drag toolbar can bypass all snapping, and Alt bypasses it for an individual gesture. Rulers and guides are editor UI and never enter page artwork.

## Strict migration and rollback data

In the 0.3 release, new documents used schema version 3. Imports validate v1/v2 against their original field allowlists before adding defaults. Existing old fields, IDs, page order, crop/filter settings and primitive chart/table groups are preserved. Migration adds only per-page `transparentBackground: false`, an empty guide list and independent default guide settings. The unchanged default artwork exports exactly as before.

Before autosave replaces a stored v1/v2 design, its exact original JSON is copied to a separate local key beginning `stencil-studio.document.v1.migration.v3.` and read back for verification. Library writes similarly retain the whole exact original library under `stencil-studio.library.v1.migration.v3.`. A backup cannot overwrite a different original. If the backup fails or is not actually stored, replacement is blocked even when the main save key is writable. The updated design stays open for JSON export. File offers the original data for download when available.

Browser storage can still fill, and clearing browser data removes its backups. Export files before clearing data or changing browsers. The older v2 application cannot consume newly added v3 fields; keep the preserved original for rollback. Configured shared workspaces validate and retain v3 documents through the same model validator; they require the matching server/app version. No service protocol, credentials, provider, audio/video engine or public 0.2 branch is changed by this document model extension.
